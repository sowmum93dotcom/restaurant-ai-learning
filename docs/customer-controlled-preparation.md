# AREA 1 controlled purchase preparation

The existing Customer Experience page accepts an explicitly granted DEMEOS continuation only in the server-confirmed controlled feed. External business items still continue to the validated external destination. Supplied media ownership and navigation remain unchanged.

Customer selects valid options and a transaction quantity only when the item explicitly allows it. Continue uses the existing My DEMEOS sign-in and registration modal, including its configured Google option. No extra account form, name, phone, delivery or service onboarding is added. The existing customer language selector controls both page presentation and provider authentication copy in all nine languages.

A one-tab session draft preserves only work/product references, exact option values, quantity and a 30-minute expiry. It never holds identity, email, address, payment or order information. The return destination is a fixed same-origin Customer Experience URL. Drafts are revalidated against current server-controlled items after authentication and again at final review. Provider session claims alone cannot authorize the preparation endpoint: the existing trusted customer resolver and repository owner exclusion are enforced independently.

Fulfilment fields are declared per controlled item. The delivery example requires street, town/city and country; it imposes no universal postcode or repeat account-name question. Collection requires no address. The service example requires only a booking date. Options already selected on the item are reviewed and are not asked again. Digital fulfilment has no address or service fields. Delivery/service details stay in page memory and are submitted solely for stateless validation, never persisted.

The final screen shows current business, item, option labels, quantity where permitted, price presentation, availability, necessary details and verification of the current customer account. The resolver exposes no provider profile details, so review states that the current account is securely verified and links to My DEMEOS privacy/control rather than inventing an email or copying private identity into the draft. Current price is the item's price presentation, not a payable total or fee calculation.

The final boundary is explicitly inactive. No order, booking, payment session, card collection, payment provider call or charge exists. Neither normal production business data nor controlled fixture records are written. The established exact query plus controlled header gate and `DEMEOS_CONTROLLED_TEST_CONTENT=disabled` remain enforced. The endpoint is routed through the existing public-config function to avoid an additional deployed function.

The browser preparation gate uses a deterministic provider adapter, not a real OAuth account or live signup. It exercises the actual preparation handler and fixtures through registration return, all nine languages and phone/tablet/desktop review, conditional fulfilment, unavailable re-check and external isolation. The existing language and supplied media/browser gates continue separately. Live provider signup remains configured by the existing Clerk integration; no provider account is created by these checks.
