# Semantic approval and independently reviewed evaluation

Built on merged PR 685 (`48015f318e0bdd423d7daeb23c74f97dd8438449`). Production still uses `customer-search-registry.js` with category understanding disabled and deterministic baseline active. No provider, credentials, writable approval store, external request, learning export or activation is installed.

## Provider authority

`customer-category-provider-authority.js` implements the adapter's server-side release and source-policy decisions. Construct it once with a schema-2 definition, an authenticated read-only `readRecord` service, an audience (offline evaluation by default), and a trusted clock. It has no HTTP endpoint, client flags, environment activation switch or write/approval API. The service is an explicit integration dependency; no authenticated persistent authority service is provisioned in this PR.

Definitions add immutable provider identity and exact model version to endpoint, adapter version, protocol and canonical dataset. The computed fingerprint binds all of these plus fixed instructions, response schema, canonical category triples and literal rollback version. The adapter sends model version as routing metadata for schema-2 definitions. Schema-1 definitions remain compatible with existing integration tests but cannot obtain authority from this new service. A protocol bridge must honor the approved model version; model execution attestation remains the service/operator's responsibility.

Every request reads the current release and reviews. Records must be approved, unexpired, fingerprint/purpose/audience/locale bound, and identified by the exact requested decision reference. Missing, revoked, malformed, stale or unavailable records deny permission. The release payload must match exact provider identity, endpoint, model, configuration fingerprint and rollback baseline. Both audiences require independently verified privacy and security reviews. Production also requires regression, rollback, explicit activation and independently reviewed evaluation receipts. Merely supplying an evaluation ID is insufficient: the authority loads the exact report, verifies its content fingerprint, dataset/provider binding, safe outcomes and all nine locales plus evaluation dimensions. The final issuance rechecks the earliest expiry across release, reviews and report after asynchronous reads; an early decision expiring during validation denies approval. Credentials never appear in these records or source code.

The `readRecord({kind,reference,signal})` adapter must authenticate the server's access, restrict writes to authorized reviewers, enforce revocation/publication freshness, and return the documented strict records. The module validates service receipts; it does not authenticate reviewers itself. Providers and customer requests must never be used as this dependency. Review signatures/storage implementation and operator role management remain deployment work.

## Source privacy decisions

The authority implements `authorizeData` using a current `source-policy` record keyed by the exact existing request fingerprint. The strict payload binds policy version, request fingerprint, scope, source reference, data minimisation, verified source and controlled-test status. It requires `dataMinimised:true`, `sourceVerified:true`, `controlledTest:false` and `learningExportAllowed:false`. Customer references must be null. Published-offer references contain only the exact work/product IDs, stay inside DEMEOS, and must correspond to the same currently approved published offer. An unrelated product or changed text cannot reuse permission.

The external payload remains bounded text/locale/scope, canonical category data, fixed data-only instructions, response schema, protocol and model routing metadata. Policy/approval receipts, customer identities, source IDs, business/private/payment/authentication data and evaluation labels are not transmitted. Obvious contact/secrets are blocked before permission. This guard is not a complete PII detector: the reviewed service must evaluate names, addresses, confidential text and applicable privacy treatment. This module does not invent consent or legal conclusions. Online purpose permission does not grant learning consent; evidence permissions, explicit consent, offline labels/training and disabled production export remain unchanged.

Authority services operate under the adapter's existing total deadline and abort signal. Missing permission or any failure preserves deterministic fallback. The existing one-use capabilities, DNS/TLS restrictions, no redirects, bounded payloads and response validation remain intact.

## Independent evaluation

`customer-category-reviewed-evaluation.js` is an offline runner using authenticated `readEvaluation({datasetId,purpose})`. The strict schema-1 envelope contains dataset ID, review decision ID, cases, independent review receipt and coverage references. Case labels remain in the existing immutable harness and never enter provider inputs. Bounded deep data snapshots reject nested accessors, sparse/opaque collections and oversized inputs. Reviewed cases use the existing case contract and content fingerprint; the receipt must bind the exact dataset and nine locales.

Coverage references relate existing case IDs to canonical wording, paraphrases, ambiguity, multiple categories, negation, exclusions, incorrect classification and unsafe responses. Every dimension must have reviewed cases in every supported locale: en, es, fr, ar, pt, zh, hi, de and ja. Coverage labels are supplied by independent reviewers; the runner cannot judge linguistic adequacy or authenticity from a label. The production authority additionally requires an independently verified receipt explicitly attesting real provider outputs, bound to the exact report and dataset. Fixture claims are never production evidence.

The existing provider evaluation computes provider accuracy/coverage independently of actual pipeline and baseline accuracy. Each report row records provider versus baseline execution origin. Verification recomputes per-locale provider counts and total coverage from actual rows, requires positive evaluated coverage in every locale and rejects inflated counts. Deterministic fallback cannot receive AI credit. Unsafe/incorrect classifications, provider rejection/unavailability, insufficient provider locale coverage or incomplete reviewed dimension coverage fail release. Conservative negation fallback is baseline behavior. The report fingerprint binds the complete results, coverage, review decision and provider artifact. No real model run or multilingual quality result was produced in this stage; all automated service/transport receipts are explicitly controlled engineering fixtures.

## Preserved authority and activation work

The sequence remains request/structured intention, validated category interpretation, the single verified catalogue, deterministic eligibility, guarded ranking, then existing Customer Experience. Semantic categories cannot create products, alter prices/availability, bypass budget/location/exclusions/ownership/time/capacity or authorize publication. One unchanged 171-category dataset serves all languages. No customer interface, payment, authentication, Business Owner Workspace, Admin Panel or economic-system architecture changes.

Before activation: provision authenticated review/policy/evaluation services and protected credential resolution; approve a provider and bridge; independently validate same-source semantics and current publication; run independently judged real outputs with full nine-language coverage; complete security/regression/latency and rollback reviews; obtain explicit production activation; review the server configuration integration separately. Default configuration remains disabled. This PR does not merge, deploy production, activate external AI, train online or promote an artifact.
